- Confidence: medium · Applies to: AGP 9.4.1 + Gradle 9.8.0 + Kotlin 2.4.20
- Source: https://kotlinlang.org/docs/gradle-configure-project.html
- Verifier: **confirmed**. Table row verified: '2.4.20 | 7.6.3-9.7.0 | 8.5.2-9.3.1'. ### 9. With AGP 9.x, Kotlin is built in: do not apply org.jetbrains.kotlin.android, and kapt is not usable.

The migration page says AGP 9.0 enables built-in Kotlin by default, the kotlin-android plugin must be removed, and org.jetbrains.kotlin.kapt is incompatible (use KSP or com.android.legacy-kapt). The AGP 9.4.1 pom still carries a runtime dependency on kotlin-gradle-plugin 2.2.10 and a KSP constraint of 2.2.10-2.0.2. Per the AGP 9.0 release notes, a higher KGP or KSP is selected by putting org.jetbrains.kotlin:kotlin-gradle-plugin:<version> (and the KSP plugin) on the top-level buildscript classpath.

- Confidence: high · Applies to: AGP 9.4.1 build setup
- Source: https://developer.android.com/build/migrate-to-built-in-kotlin
- Verifier: **confirmed**. Migration page and AGP 9.0 notes confirm built-in Kotlin by default, kotlin-android must be removed, org.jetbrains.kotlin.kapt is incompatible. AGP 9.4.1 pom/module: kotlin-gradle-plugin 2.2.10 (runtime) and KSP constraint 2.2.10-2.0.2; higher KGP/KSP via buildscript classpath is documented. Nuance: 'kapt is not usable' is too absolute; com.android.legacy-kapt (published at 9.4.1) is the supported kapt replacement, though this project should use KSP (Room 3 requires it). (https://developer.android.com/build/releases/agp-9-0-0-release-notes)
